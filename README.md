## 工程职责

下板负责DBUS、四轮麦轮底盘、底盘IMU、裁判接收、超电与无线充通信。裁判给动态功率上限和电源许可，超电给实际功率反馈，四轮电流发送前统一限流。板间遥控转发与上板安全许可共同决定整车动作。

## 模块结构体接口

驱动入口在同一结构体内保存数据引用与函数指针。数据按 `config`、`data`、`control`、`diagnostics` 分类，函数按用途分区，读取反馈可用 `motor3508.get_feedback()`。下板四轮命令入口为 `motor3508.execute()`，PID 状态放在 `motor3508.control`。算法使用共用入口，每个实例保存独立状态。

原函数继续提供，启动、任务和总线分发已接入新入口。完整入口表与调用示例见 [模块接口与目录](文档/12_模块接口与目录.md)。

## 程序流程

DBUS→遥控状态→安全与模式判定→麦轮目标→速度PID→单轮电流限幅→自适应模型预测、实测预算修正和按轮分配→FDCAN1。裁判任务独立解析并发送D6热量，通信任务转发遥控并服务超电；底盘任务连续发送D4角速度。流程图见 [启动与任务](文档/01_启动与任务.md)。

## 操作入口

| 输入 | 行为 |
| --- | --- |
| 左上 / 左中 / 左下 | 跟随 / 机械 / 机械且上板允许升降 |
| 普通模式右下 / 右中 / 右上 | 发射保险 / 摩擦轮待发 / 发射；需真实换档布防 |
| 左下档右中 / 右下 | 上板升降高位 / 低位，进入后换档执行 |
| 拨轮正向 / 负向 | 小陀螺切换 / 调头请求；需回中重新触发 |
| V、Z、X | 键鼠接管、跟随、机械 |
| G、Q、B、F | 小陀螺、调头、机械模式升降、摩擦轮 |
| 鼠标左键 / 右键 | 单发或长按连发 / 降低瞄准灵敏度 |

遥控小陀螺禁止发射，键鼠小陀螺允许发射；物理左下档占用右杆控制升降。顶部许可、两轴/IMU在线和重新布防共同影响实际执行，详细条件见 [遥控与模式](文档/02_遥控与模式.md)。

## 参数与观察变量

默认配置在 `config/application_config.c` 和 `config/peripheral_config.c`。运行时修改只在本次上电有效，验证后回填源码。

模块配置内部使用命名子结构体，按部件、模式和功能分类；每组有独立默认值初始化函数。类型、成员路径与初始化入口见 [配置与调参](文档/11_配置与调参.md)。

- 功率预测：`chassis_power_state.predicted_request_w/predicted_output_w/wheel_scale`；辨识参数在 `chassis_power_model_state.loss`，学习次数在 `estimator.updates`，默认配置在 `chassis_power_model_config`。
- 功率：`chassis_power_state.power_w/target_w/current_scale/power_feedback_valid`，斜杠表示分别查看这些成员。
- 裁判：`referee_state.info.robot_status.chassis_power_limit`、`referee_state.message[6]`、`referee_uart_diagnostics`。
- 底盘：`chassis_spin_block_reason`、`chassis_turnaround_pending`、`chassis_front_reversed`。
- 设备：`chassis_imu`、`power_communication_state`、`chassis_can_state`。

完整参数和单位见 [配置与调参](文档/11_配置与调参.md)。

## 编译与验证

打开 `MDK-ARM/infantry _down.uvprojx`，使用工程指定的ARM Compiler 5配置。源码改动后编译并查看错误/警告；编译通过不能代替电机方向、机械行程和实车安全验证。

工程根目录之外的 `My_infantry/验证/` 有实际源码测试：升降与调头、功率与裁判、陀螺EKF。测试需本机Python与GCC，覆盖软件状态和数值边界，不连接实车。

## 维护与移植

- 外设由CubeMX配置，生成后核对USER CODE、任务、回调、DMA和总线过滤；模块应有唯一接收回调分发入口。
- 协议变更时两板同步核对ID、单位、有效位和超时；CAN入队结果用于发送重试，电机执行情况通过反馈判断。
- 配置类型和源码各自留在对应板工程，公共算法两板副本需要同步维护。
- 任务tick、PID秒、转子rpm/rad/s、MIT转矩码、电流码分别处理。
- 各模块文档包含实际依赖和适用范围；当前工程仍有固定外设句柄，移植需适配这些绑定。
