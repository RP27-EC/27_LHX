## 工程职责

上板负责Yaw/Pitch云台、升降和发射；从下板接收遥控、底盘角速度与轮速，向下板发送云台角度、特殊动作许可和升降校准锁车。机械Yaw使用上板陀螺仪速度反馈并叠加底盘角速度目标前馈。

## 程序流程

通信任务更新遥控；控制任务按“IMU→升降安全快照→云台→升降”运行；独立发射任务检查许可再驱动摩擦轮/拨盘。开机归中、升降校准和手动重新布防各有独立状态，不能用遥控模式代替最终许可。流程图见 [启动与任务](文档/01_启动与任务.md)。

## 操作入口

| 输入 | 行为 |
| --- | --- |
| 左上 / 左中 / 左下 | 跟随 / 机械 / 机械且上板允许升降 |
| 普通模式右下 / 右中 / 右上 | 发射保险 / 摩擦轮待发 / 发射；需真实换档布防 |
| 左下档右中 / 右下 | 上板升降高位 / 低位，进入后换档执行 |
| 拨轮正向 / 负向 | 小陀螺切换 / 调头请求；需回中重新触发 |
| V、Z、X | 键鼠接管、跟随、机械 |
| G、Q、B、F | 小陀螺、调头、机械模式升降、摩擦轮 |
| 鼠标左键 / 右键 | 单发或长按连发 / 降低瞄准灵敏度 |

遥控小陀螺禁止发射，键鼠小陀螺允许 F/鼠标发射；物理左下档占用右杆控制升降。顶部许可、两轴/IMU在线和重新布防共同影响实际执行，详细条件见 [遥控与模式](文档/02_遥控与模式.md)。

## 参数与观察变量

默认配置在 `user/application_config.c` 和 `bottom_driven/peripheral_config.c`。运行时修改只在本次上电有效，验证后回填源码。

- 云台：`cloud_yaw_rate_target_deg_s`、`cloud_yaw_rate_deg_s`、`cloud_yaw_torque_raw`、`cloud_yaw_chassis_rate_ff_deg_s`。
- 升降：`lift_control_state`、`lift_wait_reason`、`lift_safety_state`。
- 发射：`upper_shoot_block_reason`、`shoot_control_state`、`dial_motor_tx_diagnostics`。
- 时序：`upper_task_timing`；IMU：`gimbal_imu`。

完整参数和单位见 [配置与调参](文档/10_配置与调参.md)。

## 编译与验证

打开 `MDK-ARM/infantry_up.uvprojx`，使用工程指定的ARM Compiler 5配置。源码改动后编译并查看错误/警告；编译通过不能代替电机方向、机械行程和实车安全验证。

工程根目录之外的 `My_infantry/验证/` 有实际源码测试：升降与调头、功率与裁判、陀螺EKF。测试需本机Python与GCC，覆盖软件状态和数值边界，不连接实车。

## 维护与移植

- 外设由CubeMX配置，生成后核对USER CODE、任务、回调、DMA和总线过滤；模块应有唯一接收回调分发入口。
- 协议变更时两板同步核对ID、单位、有效位和超时；CAN入队结果用于发送重试，电机执行情况通过反馈判断。
- 配置类型和源码各自留在对应板工程，公共算法两板副本需要同步维护。
- 任务tick、PID秒、转子rpm/rad/s、MIT转矩码、电流码分别处理。
- 各模块文档包含实际依赖和适用范围；当前工程仍有固定外设句柄，移植需适配这些绑定。
