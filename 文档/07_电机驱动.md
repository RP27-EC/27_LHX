# 下板四轮电机驱动

## 文件和接口

`bottom_driven/motor/motor3508/motor3508.[ch]` 控制4个3508/C620；FDCAN1反馈0x201～0x204，控制群组0x200。底盘使用速度PID，位置串级接口保留供其他动作使用。接收和发送通过统一chassis_can，不在电机模块重复定义HAL总线回调。

## 控制链和反馈

速度目标是转子rpm，各轮速度PID分别给电流原始码，再叠加本轮固定扭矩前馈，单轮先限流，再由 ChassisPower_ApplyWithTargets 根据模型、超电反馈和各轮速度误差分别分配功率，最后大端打包4个int16。反馈包含编码器、rpm、current_raw与接收时间；累计编码器处理跨圈，控制上电零点与机械输出零点要分别定义。

Motor3508_OnlineCheck检查四轮是否全部在线，用于状态观察和D5完整轮速上报。底盘任务按轮处理离线：速度和位置闭环跳过离线轮并清除该轮两级PID状态，发送出口持续将该轮电流置零，直接电流控制也生效。其他轮继续执行当前目标，恢复反馈后自动恢复控制。

驱动反馈/PID数组是内部静态状态，读取用Motor3508_GetFeedback。`chassis_power_state.wheel_feedback_valid[4]` 按ID顺序观察每轮有效性；电流可用 `feedback_raw/request_raw/output_raw` 查看，离线轮在功率模块中的转速和反馈电流观察值清零，驱动原始反馈仍可读取。

后级单轮限幅或功率比例限制使输出饱和时，驱动按 PID 加前馈的总请求撤销会加重饱和的本次积分；允许反向误差帮助退出饱和。发送失败返回HAL状态，只表示命令是否入队，不表示电机执行。

## 参数和移植

`motor3508_config.wheel[0..3]` 对应电机 ID1～ID4，每轮包含 `position`、`speed`、`feedforward`。两环 PID 独立调整，周期、电流上限和反馈超时共用。默认值位于 `Motor3508WheelConfig_Init()` 的各 ID 块，调用该函数传入 ID 可单独恢复本轮参数。

`feedforward.fixed_current_raw` 是固定扭矩对应的 C620 电流码幅值，非正值关闭。目标转速大于死区时加正前馈，小于负死区时加负前馈，死区内不加。位置模式按位置外环给出的目标速度决定方向；停机和离线轮清零。前馈默认关闭，直接电流接口保持原输入。

Watch 可查看 `motor3508.control.speed_pid[i]`、`motor3508.control.position_pid[i]` 与 `motor3508.control.requested_current_raw[i]`。请求值为 PID 加前馈的限幅前结果，最终电流查看 `chassis_power_state.output_raw[i]`。C620命令电流码与转子力矩电流不能直接当直流输入电流；功率反馈应来自实际测量。

相同DJI协议可复用驱动+PID+配置，但当前发送出口依赖chassis_can和功率适配。移植需建立唯一0x200拼帧者、配置ID过滤与中断分发，并处理功率模块依赖。反馈字节序和板间D5不同，不能直接memcpy普通反馈结构体发D5。增添同组电机需核对槽位与协议电流上限。
