## 文件分组

```text
infantry _down/
├─ config/                           应用、驱动默认参数
├─ user/
│  ├─ chassis/
│  │  └─ power/                     自适应模型、按轮分配与预算反馈
│  └─ remote/                       遥控模式与操作事件
├─ bottom_driven/
│  ├─ motor/motor3508/              底盘四轮
│  ├─ communication/
│  │  ├─ board/                     板间 CAN
│  │  ├─ chassis_can/               底盘 CAN 分发
│  │  └─ power/                     超电与无线充
│  ├─ IMU/                          BMI088 与姿态输出
│  ├─ telecontrol/                  DBUS
│  └─ referee/                      裁判串口与解析
├─ algorithms_library/
│  ├─ pid/                          PID
│  ├─ rls/                          两参数在线辨识
│  └─ attitude_ekf/                 四元数 EKF
├─ Core/                            CubeMX 外设与 RTOS 入口
├─ 文档/                            模块说明与接口索引
├─ MDK-ARM/                         Keil 工程
└─ Drivers/Middlewares/             HAL、CMSIS、FreeRTOS
```

应用默认值集中在 `config/application_config.[ch]`，驱动默认值集中在 `config/peripheral_config.[ch]`。电机文件按型号分组；应用文件按功能分组。Keil 工程分组与目录对应。

## 模块入口

| 模块变量 | 大结构体类型 | 内容 | 接口定义 |
| --- | --- | --- | --- |
| `pid_algorithm` | `PidAlgorithm` | 共用 PID 操作，调用时传入控制器实例 | [PID.h](../algorithms_library/pid/PID.h) |
| `quaternion_ekf_algorithm` | `QuaternionEkfAlgorithm` | 共用 EKF 操作，调用时传入滤波器实例 | [quaternion_ekf.h](../algorithms_library/attitude_ekf/quaternion_ekf.h) |
| `chassis_imu_driver` | `ChassisImuModule` | 底盘姿态、角速度与线加速度 | [imu.h](../bottom_driven/IMU/imu.h) |
| `motor3508` | `Motor3508Module` | 电机反馈与 PID | [motor3508.h](../bottom_driven/motor/motor3508/motor3508.h) |
| `board_link` | `BoardLinkModule` | 板间原帧、解析结果与通信诊断 | [communication.h](../bottom_driven/communication/board/communication.h) |
| `power_link` | `PowerLinkModule` | 超电、无线充及控制发送状态 | [power_communication.h](../bottom_driven/communication/power/power_communication.h) |
| `chassis_can` | `ChassisCanModule` | 底盘 CAN 收发与错误统计 | [chassis_can.h](../bottom_driven/communication/chassis_can/chassis_can.h) |
| `telecontrol` | `TelecontrolModule` | 遥控原始字节、解析结果与接收统计 | [telecontrol.h](../bottom_driven/telecontrol/telecontrol.h) |
| `referee` | `RefereeModule` | 裁判解析结果、消息有效性与诊断 | [referee.h](../bottom_driven/referee/referee.h) |
| `referee_uart_driver` | `RefereeUartModule` | 裁判 DMA 字节与串口诊断 | [referee_uart.h](../bottom_driven/referee/referee_uart.h) |
| `rls2_algorithm` | `Rls2Algorithm` | 两参数 RLS，共用操作、独立实例 | [rls2.h](../algorithms_library/rls/rls2.h) |
| `chassis_power_model_algorithm` | `ChassisPowerModelAlgorithm` | 模型校验、在线辨识、预测及四轮分配 | [chassis_power_model.h](../user/chassis/power/chassis_power_model.h) |
| `chassis_power_pi_algorithm` | `ChassisPowerControlAlgorithm` | 功率预算 PI 校验、初始化与更新 | [chassis_power_control.h](../user/chassis/power/chassis_power_control.h) |

驱动大结构体同时保存数据引用和函数指针。数据按 `config`、`data`、`control`、`diagnostics` 分类；函数直接放在同一结构体内，按初始化、读取、控制、维护和解析分区。

| 分类 | 用途 |
| --- | --- |
| `config` | 指向 `config/` 中已有的可调参数 |
| `data` | 指向现有反馈或解析结果，适合 Watch 展开观察 |
| `control` | 指向电机 PID 实例，观察误差、积分和输出 |
| `diagnostics` | 指向通信统计和错误状态 |
| 函数成员 | 直接通过模块入口调用，例如 `motor3508.get_feedback()` |

入口变量为 `const`，函数指针和数据绑定地址随程序保存。反馈仍由原接收流程更新，参数仍由原配置初始化函数加载。原函数与全局观察变量继续提供。

## 驱动访问

电机参数可通过 `motor3508.config->speed.kp` 查看或修改，反馈可通过 `motor3508.data.feedback[0].speed_rpm` 观察。控制任务使用快照接口复制同一帧的数据：

```c
Motor3508_Feedback feedback;
if (motor3508.get_feedback(1U, &feedback))
{
    // 本周期使用 feedback 中的位置、速度和电流。
}
```

底盘反馈数组按电机 ID 排列，下标从零开始。原始字节、原值与换算结果的单位在驱动头文件和 `config/peripheral_config.h` 中标注。

## 算法实例

PID 状态保存在 `PID_Controller_t`，EKF 状态保存在 `QuaternionEkf`。每个闭环、每个 IMU 使用独立实例；操作表通过 `pid_algorithm.ops`、`quaternion_ekf_algorithm.ops` 共用。

```c
PID_Controller_t loop;
QuaternionEkf attitude;

// 由调用者提供增益、限幅和实际控制周期。
pid_algorithm.ops.init(&loop, kp, ki, kd, integral_limit, output_limit, dt_s);
quaternion_ekf_algorithm.ops.init(&attitude, NULL);

output = pid_algorithm.ops.calc(&loop, target, measured);
quaternion_ekf_algorithm.ops.update(&attitude, &ekf_config, gyro, accel, dt_s);
```

底盘功率模型和实测 PI 分别通过 `chassis_power_model_algorithm.ops`、`chassis_power_pi_algorithm.ops` 调用。模型参数由 `ChassisPowerModelConfig` 保存，损耗和 RLS 状态由 `ChassisPowerModelState` 保存，预算 PI 状态由 `ChassisPowerController` 保存，文件与底盘应用放在 `user/chassis/power/`。

实例的原成员路径保留，如 `loop.Integral`、`attitude.q[]`。PID、EKF 文件夹可分别复制使用，算法代码使用 C 标准库。

## 初始化与调用

1. CubeMX 完成时钟、GPIO、SPI、CAN/FDCAN、串口和 DMA 配置。
2. 调用本板 `LowerPeripheralConfig_InitAll()`、`LowerApplicationConfig_InitAll()`，加载默认参数。
3. 依原顺序调用各驱动模块 `init` 或 `start`，完成反馈、闭环和通信初始化。
4. 周期任务通过模块函数成员更新状态和执行命令；接收中断通过分发接口解析数据。

当前已迁移启动、任务、总线分发处的驱动调用，以及控制中的 PID、EKF 调用。应用内部保留部分原驱动函数调用，可按模块逐步迁移。

## 移植步骤

1. 复制对应驱动文件夹，以及所需算法文件夹。
2. 从 `config/` 提取该驱动的配置类型、变量和初始化函数。
3. 按目标板配置外设，修改驱动使用的句柄、引脚和 CAN ID。
4. 将 `.c` 加入工程，添加模块、配置和算法头文件目录。
5. 先初始化配置，再调用模块初始化；按驱动要求绑定接收回调和控制周期。
6. 核对反馈类型、单位、方向和在线状态，再接入控制任务。

当前驱动适用于对应系列 STM32 + HAL 工程。每种驱动按本板资源绑定一个模块入口，多台同型号电机由反馈和 PID 数组区分。其他 HAL 系列需修改外设适配代码。各模块的外设配置与协议说明见工程首页索引。
